# Читанка: налаштування теми — Практична робота 6.1, варіант 3

Застосунок-читанка, вигляд якого змінюється з екрана налаштувань.

## Запуск

```bash
flutter create .        # один раз: згенерує android/ios/web тощо (наявні файли не перезаписує)
flutter pub get
flutter analyze
flutter run
```


## Структура `lib/`

```
lib/
├── main.dart, app.dart
├── models/    accent_option, theme_settings, text_settings, sample_article  (незмінні класи)
├── state/     theme_settings_model, text_settings_model (ChangeNotifier)
│              theme_scope, text_scope (InheritedNotifier), app_theme
├── screens/   reading_screen, settings_screen
└── widgets/   article_body, accent_picker, theme_mode_selector, settings_preview
```

## Таблиця стану

| Дані | Де живуть | Чому саме там |
|---|---|---|
| Застосовані `themeMode` + акцент | `ThemeSettingsModel` → `ThemeScope` над `MaterialApp` | Від них залежать `theme`, `darkTheme`, `themeMode` у `MaterialApp`; змінюються з екрана налаштувань, а діють на весь застосунок — це стан застосунку |
| Застосований розмір шрифту | `TextSettingsModel` → `TextScope` | Змінюється на екрані налаштувань, використовується на екрані читання. Окрема модель, щоб зміна розміру не чіпала `MaterialApp` |
| Чернетка режиму та акценту (до «Застосувати тему») | `State` екрана налаштувань, `setState` | Ефемерний: потрібен лише цьому екрану для попереднього перегляду |
| Значення слайдера під час перетягування | `State` екрана налаштувань, `setState` | Ефемерний: у модель потрапляє лише в `onChangeEnd` |

На етапі 1 застосовані значення жили в `_ReaderAppState` (найближчий спільний предок) і йшли вниз параметрами та колбеками.

## Як працює попередній перегляд

Режим і акцент вибираються як чернетка й видні в блоці «Попередній перегляд»; у застосунок потрапляють кнопкою «Застосувати тему». Розмір шрифту в перегляді змінюється під час перетягування, а в застосунок потрапляє після відпускання повзунка. «Скинути до типових» скидає обидві моделі та чернетку.

## Журнал перебудов (етап 2)

У `build()` ключових віджетів стоїть `debugPrint('build: <Віджет>')`.

Очікувана поведінка за кодом (звірте зі своєю консоллю):

| Дія | Що перебудовується |
|---|---|
| Перетягування слайдера | `SettingsScreen`, `SettingsPreview` |
| Відпускання слайдера | `ArticleBody` (залежить від `TextScope`). `_ThemedApp` (MaterialApp) **не** перебудовується |
| «Застосувати тему» | `_ThemedApp` (MaterialApp), далі віджети, що залежать від `Theme`: `ArticleBody`, `SettingsScreen` (+ `SettingsPreview`) |
| «Скинути до типових» | обидві моделі: `_ThemedApp` (якщо тема змінилась), `ArticleBody`, `SettingsScreen` |
